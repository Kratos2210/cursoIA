A veces no quieres un párrafo, quieres **datos ordenados** (un JSON, una fila de Excel). Con `with_structured_output` + un molde **Pydantic**, el modelo llena exactamente los campos que defines.

<Box kind="def" label="◈ Definición · Salida estructurada">

**Salida estructurada** es obligar al modelo a responder con un **objeto de forma conocida** en lugar de prosa libre. Tú declaras la forma (qué campos hay, de qué tipo, cuáles son obligatorios) y recibes un objeto de Python ya validado, no un texto que tengas que interpretar con expresiones regulares.

Es la frontera entre una demo y un sistema: un párrafo hay que leerlo; un objeto con `.severidad` y `.tabla` se guarda en una base de datos, dispara una alerta o se compara con el de ayer.

<DefList>
  <Term>Pydantic</Term>
  <Def>La librería con la que se declara la forma: una clase con campos tipados y descripciones. Esas descripciones **las lee el modelo** — son parte del prompt, no comentarios.</Def>
  <Term>with_structured_output(Modelo)</Term>
  <Def>Envuelve al LLM para que su respuesta se ajuste al esquema y llegue ya convertida en una instancia de tu clase. Por debajo usa el mismo mecanismo que las herramientas (Módulo 07).</Def>
  <Term>tagging / extracción</Term>
  <Def>Los dos usos clásicos. *Tagging*: clasificar en casillas que tú definiste (sentimiento, idioma, severidad). *Extracción*: sacar entidades de un texto (nombres, montos, fechas) a una lista de objetos.</Def>
</DefList>

</Box>

<Box kind="analogy" label="◆ Analogía">

Es ponerle **anteojeras** al modelo: deja de conversar y su única misión es rellenar tu formulario. Pydantic valida los tipos: si dijiste que `edad` es un número, no dejará pasar texto.

</Box>

```python title="extraction.ipynb · extraer una lista"
from pydantic import BaseModel, Field
from typing import Optional, List

class Persona(BaseModel):
    """Una persona mencionada en el texto."""
    nombre: str = Field(description="Nombre de la persona")
    edad: Optional[int] = Field(default=None, description="Edad si se menciona")

class Extraccion(BaseModel):
    personas: List[Persona]   # busca TODAS, no solo una

extractor = llm.with_structured_output(Extraccion)
r = extractor.invoke("Ana tiene 30 años y su hijo Luis, 5.")
for p in r.personas:
    print(p.nombre, "->", p.edad)
```

```text title="▸ deberías ver"
Ana -> 30
Luis -> 5
```

El mismo patrón sirve para **etiquetar/clasificar** (tagging): defines las casillas y el modelo las marca.

```python title="Tagging.ipynb · clasificar"
class Etiqueta(BaseModel):
    sentimiento: str = Field(description="positivo | negativo | neutro")
    idioma: str = Field(description="idioma detectado")

clasificador = llm.with_structured_output(Etiqueta)
print(clasificador.invoke("I love this new system, it's super fast!"))
```

<Box kind="warn" label="▲ Un campo obligatorio que no está en el texto → el modelo lo inventa">

Si declaras un campo como obligatorio (sin `Optional`) y el texto **no trae ese dato**, el modelo tiene que llenarlo igual… así que se lo **inventa** para no dejar el molde incompleto. La cura es doble: marca como `Optional` (con `default=None`) todo lo que *pueda* faltar, y **valida a mano lo crítico** después de recibir el objeto. Un molde que obliga a rellenar es un molde que invita a alucinar.

</Box>

Crea un molde `Producto` (nombre, precio, en_stock: bool) y extráelo de una frase desordenada. Añade un campo `Optional` y prueba con una frase donde ese dato no aparezca.

<Solution summary="Ver una solución">

```python title="solución"
class Producto(BaseModel):
    """Un producto mencionado en el texto."""
    nombre: str = Field(description="Nombre del producto")
    precio: float = Field(description="Precio en soles")
    en_stock: bool = Field(description="Si hay stock disponible")
    color: Optional[str] = Field(default=None, description="Color, si se menciona")

extractor = llm.with_structured_output(Producto)
print(extractor.invoke("Sí tenemos la camilla plegable, cuesta 350 soles"))
# color saldrá None: el modelo NO lo inventa porque es Optional
```
