### Antes de empezar: prepara tu computadora

Si nunca programaste, este es tu punto de partida. Necesitas **tres cosas**: una terminal (ya la tienes), `git` (para traerte el curso) y un editor para escribir tus archivos. Nada más — de Python y las librerías se encarga `uv`, que instalas en la primera línea del bloque de instalación.

#### 1 · La terminal (tu línea de comandos)

La **terminal** es una ventana donde escribes órdenes con el teclado en vez de hacer clic. Todos los comandos del curso se escriben ahí. Cómo abrirla:

- **Windows:** menú Inicio → escribe `PowerShell` → Enter.
- **macOS:** `Cmd + Espacio` → escribe `Terminal` → Enter.
- **Linux:** `Ctrl + Alt + T` (o busca "Terminal" en tus aplicaciones).

<Box kind="analogy" label="◆ Analogía">

La terminal es como enviarle notas escritas a tu computadora en lugar de señalarle cosas con el dedo. Al principio intimida porque no hay botones; pero cada comando de este curso está listo para **copiar y pegar**, así que no tienes que memorizar nada.

</Box>

#### 2 · Instala `git`

**git** es el programa que se baja el material del curso a tu computadora (y, más adelante, el que versiona tu código). Hoy lo usarás para **un solo comando**. Comprueba primero si ya lo tienes:

```bash title="terminal · ¿ya tengo git?"
git --version
```

Si responde algo como `git version 2.43.0`, ya está: sigue al paso 3. Si dice `command not found`:

- **Windows:** descárgalo de [git-scm.com/download/win](https://git-scm.com/download/win) e instálalo con las opciones por defecto (Siguiente → Siguiente).
- **macOS:** escribe `git --version` y macOS mismo te ofrecerá instalar las *Command Line Tools*; acepta. (O `brew install git` si usas Homebrew.)
- **Linux:** `sudo apt install git` (Debian/Ubuntu) o `sudo dnf install git` (Fedora).

Cierra la terminal, abre una nueva y vuelve a comprobar con `git --version`.

#### 3 · Instala VS Code (tu editor)

Para escribir los archivos `.py` necesitas un editor de texto para programadores. El más usado es **Visual Studio Code**, gratis: descárgalo de [code.visualstudio.com](https://code.visualstudio.com) e instálalo como cualquier programa.

Los archivos que escribas los guardarás con nombre terminado en `.py` (por ejemplo `mi_01.py`). Esa terminación es la que le dice a todo el mundo —y a `uv`— que dentro hay código Python. VS Code además trae su propia terminal integrada (menú *Terminal → Nueva terminal*), muy cómoda para no cambiar de ventana.

### Instalación: el día 1 completo

Todo el curso vive en un repositorio público. Te lo traes con `git clone`, entras en la carpeta de trabajo y dejas que `uv` haga el resto:

```bash title="terminal · de cero a instalado"
# 1 · Instala uv (gestiona Python, el entorno y las librerías).
#     macOS o Linux:
curl -LsSf https://astral.sh/uv/install.sh | sh
#     Windows (en PowerShell):
#     powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
#     ⚠️ Después, CIERRA la terminal y abre una nueva.

# 2 · Trae el curso a tu computadora
git clone https://github.com/Kratos2210/cursoIA.git

# 3 · Entra en la carpeta de trabajo (aquí vives todo el curso)
cd cursoIA/curso_ejemplos

# 4 · Crea tu .env a partir de la plantilla, y pega tu llave dentro
cp .env.example .env        # Windows PowerShell:  copy .env.example .env

# 5 · Instala Python y todas las librerías, en las versiones exactas del curso
uv sync
```

Cada comando hace una cosa distinta y conviene no confundirlas:

| Comando | Qué hace |
| --- | --- |
| El instalador de `uv` | Lo único que instalas a mano. Si después ves `command not found: uv`, no abriste una terminal nueva. |
| `git clone` | Copia el repositorio completo a tu disco. Se hace **una sola vez**. |
| `cp .env.example .env` | Crea tu archivo de secretos a partir de la plantilla comentada. El `.env.example` sí está en el repo; tu `.env` **nunca** (lo bloquea el `.gitignore`). |
| `uv sync` | Lee `pyproject.toml` + `uv.lock`, crea el entorno virtual (`.venv`) e instala las versiones exactas. **Si te falta Python, también lo instala.** |

Fíjate en lo que *no* tienes que hacer: no creas el entorno virtual, no lo activas y no instalas Python. De las tres cosas se encarga `uv sync`, y `uv run` ya ejecuta dentro de ese entorno. El paso 4 es el único que te pide algo tuyo — la llave. Es lo que viene ahora.

<Box kind="def" label="◈ Por qué `uv sync` y no `uv add` uno por uno">

`uv add` va añadiendo librerías de una en una a un proyecto vacío; `uv sync` instala de golpe la lista ya escrita en `pyproject.toml`, respetando `uv.lock`. Esa diferencia importa: el lockfile fija las **versiones exactas** con las que está probado el curso, así que no te toca lidiar con un cambio de API de LangChain publicado la semana pasada. Los extras opcionales (RAG local, servidor, vector DB) se instalan cuando llegues a su módulo, con `uv sync --extra emb` y compañía — cada concepto te dice cuál.

</Box>

<Box kind="def" label="◈ Si `uv sync` se traba, es normal (y tiene arreglo de una línea)">

La instalación puede tener algún tropiezo según tu equipo —el más común es en **Mac Intel**, donde un paquete que arrastra Chroma ya no trae binario—. No es tu código, y ninguno te frena de verdad: todos los casos están reunidos, con su causa y su solución de una línea, en el anexo **[Errores comunes](/recurso/faq)**. El hábito correcto es el del [Concepto 0b](/concepto/0b-python-minimo): lee la **última línea** de lo que salió en tu terminal y búscala ahí.

</Box>

En este curso hay **una sola carpeta de trabajo**: `cursoIA/curso_ejemplos/`. Ahí vives, ahí escribes tus archivos y ahí corres todo. Importa más de lo que parece, porque `uv` elige el entorno buscando el `pyproject.toml` **más cercano hacia arriba**: fuera de esa carpeta, el mismo comando que te funcionaba deja de hacerlo. Si algo falla, la primera pregunta no es "¿me faltó instalar algo?" sino **"¿estoy parado en `curso_ejemplos/`?"** — y el verificador de más abajo te lo responde en su paso 2.

### Consigue tu llave (paso a paso)

El modelo vive en los servidores de otra empresa; tu programa se identifica ante ellos con una **llave API**. Conseguirla es gratis y toma un minuto. **Tienes dos proveedores para elegir**, y el curso funciona igual con cualquiera de los dos.

<Box kind="analogy" label="◆ Cuál elegir (y por qué te vas a acabar pasando a Groq)">

**Gemini** es el camino por defecto del curso. **Groq** sirve modelos abiertos con un cupo gratuito *mucho* más generoso y respuestas bastante más rápidas.

La cuota gratuita de Gemini se agota en una tarde de práctica: verás un `429 RESOURCE_EXHAUSTED` y creerás que rompiste algo. No rompiste nada. Si vas a hacer los ejercicios del tirón, **empieza directamente en Groq**. Puedes tener las dos llaves y cambiar con una línea del `.env`.

</Box>

Para empezar, con Gemini o Groq te basta. Pero el conmutador entiende **más proveedores** — `openai`, `anthropic` (Claude), `openrouter` y `deepseek`, además de `ollama` en tu máquina — todos con la misma línea del `.env`. Cuándo y por qué elegir cada uno (pago vs. open weights, precios reales, dónde corre) lo ves en el [Concepto 18b · Elegir modelo y proveedor](/concepto/18b-elegir-modelo-y-proveedor).

#### Opción A · Gemini

1. Entra a [aistudio.google.com](https://aistudio.google.com).
2. Inicia sesión con tu cuenta de Google (la misma de Gmail sirve).
3. Haz clic en el botón **"Create API key"** (Crear llave API).
4. **Copia** la llave que aparece — empieza con `AIza…`.
5. Pégala en tu archivo `.env`, **reemplazando** el texto de relleno `tu_llave_secreta`.

El paso 5 es el que más confunde. Tu `cp .env.example .env` copió una plantilla llena de comentarios y de textos de relleno; tú cambias el de tu proveedor por tu llave real:

```ini title=".env · ANTES (lo que trae la plantilla)"
LLM_PROVIDER=google
GOOGLE_API_KEY=tu_llave_secreta_aqui
```

```ini title=".env · DESPUÉS (con tu llave real, sin comillas ni espacios)"
LLM_PROVIDER=google
GOOGLE_API_KEY=AIzaSyD-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

#### Opción B · Groq

1. Entra a [console.groq.com/keys](https://console.groq.com/keys).
2. Inicia sesión (con Google o GitHub, no hace falta tarjeta).
3. Haz clic en **"Create API Key"** y ponle cualquier nombre.
4. **Copia** la llave — empieza con `gsk_…`. Solo se muestra *una vez*.
5. Pégala en el `.env` y cambia el proveedor:

```ini title=".env · con Groq"
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Eso es todo. Los ejemplos no cambian: todos llaman a `util.crear_llm()`, que lee el `.env` y construye el modelo del proveedor activo — nunca instancias un modelo a mano. Cambiar de proveedor es una línea del `.env`; el cómo y el porqué de esa "fábrica de modelos" (y cuándo conviene cada proveedor) lo ves en el [Concepto 18b](/concepto/18b-elegir-modelo-y-proveedor).

<Box kind="warn" label="▲ Léelo hoy, te ahorrará una tarde: los modelos se apagan">

Fíjate en que arriba **no pusiste ningún modelo**, solo el proveedor: cada uno trae el suyo de fábrica. Eso es deliberado, y conviene que sepas por qué desde el primer día.

**Los proveedores retiran modelos cada pocos meses.** Cualquier nombre de modelo que leas en este curso —o en cualquier tutorial— es una **foto con fecha**, no una verdad permanente. Le pasó a este mismo curso: Groq apagó `qwen/qwen3-32b`, que era su modelo por defecto aquí, en julio de 2026.

Así que si algún día tu programa responde `model not found`, `model_decommissioned` o `has been deprecated`, **no rompiste nada y tu llave está bien**. Se arregla en 30 segundos y sin tocar código:

```ini title=".env · el interruptor maestro"
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LLM_MODELO=openai/gpt-oss-120b
```

Copias un ID vigente y lo pegas en `LLM_MODELO`. Esa línea **gana sobre cualquier default del curso**, así que no dependes de que nosotros actualicemos el material. De dónde sacas el ID, en este orden:

1. La [tabla de modelos vigentes del cheat sheet](/recurso/cheat-sheet) — lleva su fecha de verificación.
2. La **página oficial del proveedor**, que siempre va por delante de nosotros: [Groq](https://console.groq.com/docs/models) · [Google](https://ai.google.dev/gemini-api/docs/models) · [OpenAI](https://platform.openai.com/docs/models) · [Anthropic](https://docs.anthropic.com/en/docs/about-claude/models) · [OpenRouter](https://openrouter.ai/models) · [Ollama](https://ollama.com/library).

Esta es la razón de fondo por la que en este curso el modelo vive en el `.env` y nunca dentro del código.

</Box>

Si más adelante haces RAG y mueves el chat a Groq (que no ofrece embeddings), añadirás `EMBEDDINGS_PROVIDER=fastembed` para calcularlos en tu propia máquina, sin cuota. Se explica en el [Concepto 11](/concepto/11-rag-profesional) — por ahora no hace falta.

### El último paso: comprueba que todo quedó bien

Antes de escribir una sola línea de código, el curso trae un verificador que responde de una vez a la pregunta del día 1 — *¿está todo listo?*:

```bash title="terminal · el chequeo de entorno"
uv run python env_utils.py
```

```text title="▸ deberías ver (algo así)"
1. Python
  ✔ Python 3.12.13
2. La carpeta de trabajo
  ✔ estás en la carpeta del curso: .../cursoIA/curso_ejemplos
  ✔ usando el entorno virtual de esta carpeta (.venv)
3. Las librerías (instalación base)
  ✔ langchain 1.3.14
  ✔ langgraph 1.2.8
  ...
4. El archivo .env
  ✔ .env encontrado
5. El proveedor del modelo
  ✔ LLM_PROVIDER=google
6. La llave
  ✔ GOOGLE_API_KEY presente (AIzaSy…, 39 caracteres)

  ✔ Entorno listo.
```

Si algo falta, no verás un pantallazo de error de Python: verás una línea `✘` **con su arreglo debajo**. Los tres fallos del primer día son siempre los mismos — no existe el `.env`, la llave sigue siendo el texto de relleno (copiaste la plantilla pero no pegaste nada), o `LLM_PROVIDER` está mal escrito.

Ese chequeo confirma que la llave **está**, no que **sirva**. Para confirmarlo de verdad hace falta una llamada real, y por eso va detrás de un interruptor aparte (gasta 1 de cuota):

```bash title="terminal · la prueba de fuego"
uv run python env_utils.py --ping
```

```text title="▸ deberías ver"
8. Llamada real al proveedor (--ping)
  ✔ el modelo respondió: 'listo'
  ✔ tu entorno habla con el LLM. Ya puedes correr 01_primer_modelo.py
```

Es también el único chequeo que distingue un ID de modelo **vigente** de uno que el proveedor ya apagó: si te dice que el modelo no existe, no rompiste nada — es lo que cuenta la caja de arriba, y se arregla con la línea `LLM_MODELO` de tu `.env`.

<Box kind="def" label="◈ Definición · API key">

Una **API key** (llave de acceso) es una contraseña que identifica a tu programa ante el servicio de Google. En el plan gratuito de Gemini **no cuesta nada**, pero se trata como cualquier contraseña: **no se comparte, no se pega en un chat y nunca se sube a internet** (por eso vive en el `.env`, un archivo que dejas fuera de git). Si alguien la ve, revócala y crea otra.

</Box>

<Box kind="analogy" label="◆ ¿Y si no sé qué es git?">

Acabas de usarlo sin saberlo. **git** es el sistema que versiona código: guarda la historia de un proyecto y permite copiarlo entero con un comando. Hoy solo necesitas ese comando —`git clone`, que se hace una vez y ya está—; el resto (ramas, commits, pull requests) llega en el [Concepto 37](/concepto/37-git-flujo-de-trabajo), cuando tenga sentido.

Lo que sí conviene quedarse hoy es la otra mitad: el repositorio trae un **`.gitignore`**, y ahí dentro está la línea `.env`. Eso es justo lo que evita que tu llave se escape cuando empieces a versionar tu propio trabajo. Regla de oro: **el `.env` es secreto y no se sube a ningún lado**. El `.env.example` sí viaja en el repo — porque es una plantilla sin llaves reales.

</Box>
