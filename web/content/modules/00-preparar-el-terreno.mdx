<LevelBanner level={1} title="Empieza la Ruta 1 · Fundamentos">

Preparas el terreno y haces tu primera llamada: qué es un LLM, cómo hablarle desde Python y la interfaz que usarás durante todo el curso.

</LevelBanner>

Un modelo de lenguaje (LLM) como Gemini o Qwen sabe conversar, pero por sí solo *no* calcula con exactitud, no recuerda charlas anteriores y no conoce tus documentos privados. Estas librerías resuelven justo eso.

<Box kind="analogy" label="◆ Analogía">

Piensa en un **LLM** como un empleado brillante recién contratado: habla muchos idiomas y sabe de casi todo… pero llegó sin computadora, sin acceso a tu base de datos y con amnesia cada mañana. **LangChain, RAG y LangGraph** son las herramientas de oficina que lo vuelven realmente útil.

</Box>

### Los tres protagonistas

<Grid3>

<Card num="pieza 1" title="LangChain">

La caja de piezas estándar: modelos, prompts, parsers, herramientas. Bloques que encajan entre sí.

</Card>

<Card num="técnica" title="RAG">

No es una librería, es una *técnica*: darle al modelo tus documentos como "chuleta" para responder con datos reales.

</Card>

<Card num="pieza 2" title="LangGraph">

El orquestador: agentes que piensan en ciclo (pensar → actuar → observar), recuerdan y sobreviven a fallos.

</Card>

### Antes de empezar: prepara tu computadora

Si nunca programaste, este es tu punto de partida. Necesitas **tres cosas**: una terminal (ya la tienes), `uv` (lo instalas en un comando) y un editor para escribir tus archivos. Nada más.

#### 1 · La terminal (tu línea de comandos)

La **terminal** es una ventana donde escribes órdenes con el teclado en vez de hacer clic. Todos los comandos del curso se escriben ahí. Cómo abrirla:

- **Windows:** menú Inicio → escribe `PowerShell` → Enter.
- **macOS:** `Cmd + Espacio` → escribe `Terminal` → Enter.
- **Linux:** `Ctrl + Alt + T` (o busca "Terminal" en tus aplicaciones).

<Box kind="analogy" label="◆ Analogía">

La terminal es como enviarle notas escritas a tu computadora en lugar de señalarle cosas con el dedo. Al principio intimida porque no hay botones; pero cada comando de este curso está listo para **copiar y pegar**, así que no tienes que memorizar nada.

</Box>

#### 2 · Instala `uv`

`uv` es la herramienta que gestiona tu Python y tus librerías (y si te falta Python, `uv` lo instala solo). Pega en tu terminal el comando de tu sistema:

```bash title="terminal · instalar uv"
# macOS o Linux:
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (en PowerShell):
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**Cierra la terminal y abre una nueva** (para que reconozca el nuevo programa) y comprueba que quedó instalado:

```bash title="terminal · verificar"
uv --version
```

```text title="▸ deberías ver (algo así)"
uv 0.9.x
```

Si en cambio dice `command not found: uv`, no abriste una terminal nueva o la instalación no terminó: repite el comando y vuelve a abrir la terminal.

#### 3 · Instala VS Code (tu editor)

Para escribir los archivos `.py` necesitas un editor de texto para programadores. El más usado es **Visual Studio Code**, gratis: descárgalo de [code.visualstudio.com](https://code.visualstudio.com) e instálalo como cualquier programa.

Para crear tu primer archivo: abre VS Code → menú *Archivo → Nuevo archivo* → menú *Archivo → Guardar como…* y ponle un nombre que termine en `.py` (por ejemplo `main.py`). Esa terminación es la que le dice a todo el mundo —y a `uv`— que dentro hay código Python. VS Code además trae su propia terminal integrada (menú *Terminal → Nueva terminal*), muy cómoda para no cambiar de ventana.

### Instalación (con `uv`)

```bash title="terminal · setup.sh"
# Crea el proyecto e instala lo básico para empezar
uv init mi-curso-ia && cd mi-curso-ia
uv add langchain langgraph python-dotenv

# Los dos clientes de modelo. langchain-openai no es "para OpenAI":
# es para CUALQUIER API que hable su dialecto — Groq, Ollama, Together…
uv add langchain-google-genai langchain-openai

# Crea el .env con tu llave (NUNCA lo subas a git). Elige UNA:
echo "LLM_PROVIDER=google"                    >  .env   # opción A: Gemini
echo "GOOGLE_API_KEY=tu_llave_secreta"        >> .env

# echo "LLM_PROVIDER=groq"                    >  .env   # opción B: Groq
# echo "GROQ_API_KEY=gsk_tu_llave_secreta"    >> .env
```

Con esto arrancas. Las demás librerías (RAG, re-ranking, producción…) las añades con un `uv add` cuando llegues a su nivel — cada concepto te dice cuál necesita.

Esos comandos hacen dos cosas distintas y conviene no confundirlas. `uv init` crea la carpeta del proyecto con un `pyproject.toml` **vacío de dependencias**. `uv add` es lo que las escribe ahí dentro *y* las instala. Si te saltas los `uv add`, tienes un proyecto perfectamente válido… que no sabe nada de LangChain.

<Box kind="def" label="◈ Si algún `uv add` se traba, es normal (y tiene arreglo de una línea)">

La instalación puede tener algún tropiezo según tu equipo —el más común es en **Mac Intel**, donde un paquete que arrastra Chroma ya no trae binario—. No es tu código, y ninguno te frena de verdad: todos los casos están reunidos, con su causa y su solución de una línea, en el anexo **[Errores comunes](/recurso/faq)**. El hábito correcto es el del [Concepto 0b](/concepto/0b-python-minimo): lee la **última línea** de lo que salió en tu terminal y búscala ahí.

</Box>

<Box kind="analogy" label="◆ Dónde estás parado importa (la regla de oro de uv)">

`uv` elige el entorno buscando el `pyproject.toml` **más cercano hacia arriba** desde tu carpeta actual. Por eso el *mismo* comando funciona en una carpeta y falla en la de al lado, y por eso el curso te pide siempre `cd` antes de ejecutar. Cuando dudes, pregúntale a Python qué entorno está usando de verdad:

```bash title="diagnóstico · ¿qué .venv estoy usando?"
uv run python -c "import sys; print(sys.prefix)"
# .../mi-curso-ia/.venv   ← el tuyo, el que tiene tus uv add
# .../otro-proyecto/.venv ← estás en la carpeta equivocada: haz cd
```

En este curso hay **una sola carpeta de trabajo**: `mi-curso-ia/`. Ahí vives, ahí escribes tus archivos y ahí traes las librerías con `uv add`. Si un comando te falla, la primera pregunta no es "¿me faltó instalar algo?" sino **"¿estoy parado en `mi-curso-ia/`?"**. Nueve de cada diez veces, ese es el problema.

</Box>

### Consigue tu llave (paso a paso)

El modelo vive en los servidores de otra empresa; tu programa se identifica ante ellos con una **llave API**. Conseguirla es gratis y toma un minuto. **Tienes dos proveedores para elegir**, y el curso funciona igual con cualquiera de los dos.

<Box kind="analogy" label="◆ Cuál elegir (y por qué te vas a acabar pasando a Groq)">

**Gemini** es el camino por defecto del curso. **Groq** sirve `qwen/qwen3-32b` con un cupo gratuito *mucho* más generoso y respuestas bastante más rápidas.

La cuota gratuita de Gemini se agota en una tarde de práctica: verás un `429 RESOURCE_EXHAUSTED` y creerás que rompiste algo. No rompiste nada. Si vas a hacer los ejercicios del tirón, **empieza directamente en Groq**. Puedes tener las dos llaves y cambiar con una línea del `.env`.

</Box>

Para empezar, con Gemini o Groq te basta. Pero el conmutador entiende **más proveedores** — `openai`, `anthropic` (Claude), `openrouter` y `deepseek`, además de `ollama` en tu máquina — todos con la misma línea del `.env`. Cuándo y por qué elegir cada uno (pago vs. open weights, precios reales, dónde corre) lo ves en el [Concepto 18b · Elegir modelo y proveedor](/concepto/18b-elegir-modelo-y-proveedor).

#### Opción A · Gemini

1. Entra a [aistudio.google.com](https://aistudio.google.com).
2. Inicia sesión con tu cuenta de Google (la misma de Gmail sirve).
3. Haz clic en el botón **"Create API key"** (Crear llave API).
4. **Copia** la llave que aparece — empieza con `AIza…`.
5. Pégala en tu archivo `.env`, **reemplazando** el texto de relleno `tu_llave_secreta`.

El paso 5 es el que más confunde. El comando de instalación te dejó un `.env` con un texto de ejemplo; tú lo cambias por tu llave real:

```ini title=".env · ANTES (lo que creó el comando)"
GOOGLE_API_KEY=tu_llave_secreta
```

```ini title=".env · DESPUÉS (con tu llave real, sin comillas ni espacios)"
LLM_PROVIDER=google
GOOGLE_API_KEY=AIzaSyD-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

#### Opción B · Groq con `qwen/qwen3-32b`

1. Entra a [console.groq.com/keys](https://console.groq.com/keys).
2. Inicia sesión (con Google o GitHub, no hace falta tarjeta).
3. Haz clic en **"Create API Key"** y ponle cualquier nombre.
4. **Copia** la llave — empieza con `gsk_…`. Solo se muestra *una vez*.
5. Pégala en el `.env` y cambia el proveedor:

```ini title=".env · con Groq"
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Eso es todo. Los ejemplos no cambian: todos llaman a `util.crear_llm()`, que lee el `.env` y construye el modelo del proveedor activo — nunca instancias un modelo a mano. Cambiar de proveedor es una línea del `.env`; el cómo y el porqué de esa "fábrica de modelos" (y cuándo conviene cada proveedor) lo ves en el [Concepto 18b](/concepto/18b-elegir-modelo-y-proveedor).

Si más adelante haces RAG y mueves el chat a Groq (que no ofrece embeddings), añadirás `EMBEDDINGS_PROVIDER=fastembed` para calcularlos en tu propia máquina, sin cuota. Se explica en el [Concepto 11](/concepto/11-rag-profesional) — por ahora no hace falta.

<Box kind="def" label="◈ Definición · API key">

Una **API key** (llave de acceso) es una contraseña que identifica a tu programa ante el servicio de Google. En el plan gratuito de Gemini **no cuesta nada**, pero se trata como cualquier contraseña: **no se comparte, no se pega en un chat y nunca se sube a internet** (por eso vive en el `.env`, un archivo que dejas fuera de git). Si alguien la ve, revócala y crea otra.

</Box>

<Box kind="analogy" label="◆ ¿Y si no sé qué es git?">

Verás mencionado **git** y un `.gitignore` aquí y allá. Si no sabes qué son, **ignóralos por ahora**: son herramientas para versionar código y no hacen falta para seguir el curso. Lo único que importa quedarte hoy es esto: **el `.env` es secreto y no se sube a ningún lado**. Cuando más adelante uses git, el `.gitignore` es justo lo que evita que esa llave se escape.

</Box>

<Box kind="practice" label="▸ Para practicar">

Instala lo del bloque básico y consigue tu llave: en **aistudio.google.com** (Gemini) o en **console.groq.com/keys** (Groq). Verifica que `.env` exista y esté en tu `.gitignore`. Las demás librerías las instalarás cuando llegues a cada nivel.

<Solution summary="Ver una solución">

```bash title="solución · verificación en 4 comandos"

```

Si el último comando dice `No module named 'dotenv'`, no es tu código: te faltó el `uv add python-dotenv`, o estás en otra carpeta. Repasa el aviso de arriba.

</Solution>

</Box>
