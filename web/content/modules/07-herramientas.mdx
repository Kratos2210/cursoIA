Una **herramienta** es una función de Python que le "prestas" al modelo. El decorador `@tool` la convierte en algo que la IA puede invocar sola.

<Box kind="def" label="◈ Definición · Herramienta (tool)">

Una **herramienta** es una función de Python descrita de forma que el modelo pueda decidir *cuándo* usarla y *con qué argumentos*. Nada más. El modelo no ejecuta código: **pide** que se ejecute, y tu programa obedece o no.

Ese matiz es la clave de seguridad de todo el curso. Cuando lees "el agente consultó la base de datos", lo que ocurrió es que el modelo devolvió un mensaje diciendo *"me gustaría llamar a `consultar_bd` con estos argumentos"*, y fue tu código —no el modelo— quien decidió llamarla.

<DefList>
  <Term>@tool</Term>
  <Def>El decorador que convierte la función en herramienta. Lee el nombre, los tipos de los argumentos y el **docstring** para armar la descripción.</Def>
  <Term>el docstring es el prompt</Term>
  <Def>La descripción no es documentación para ti: es **lo único** que el modelo lee para elegir. Un docstring vago produce un agente que elige mal. Escríbelo pensando en quién lo va a leer.</Def>
  <Term>tool_call</Term>
  <Def>La petición que emite el modelo: nombre de la herramienta + argumentos en JSON. Viaja dentro de un `AIMessage`, en el campo `tool_calls`.</Def>
</DefList>

</Box>

<Box kind="analogy" label="◆ Analogía">

Darle herramientas al modelo es como darle a un empleado nuevo **acceso al sistema de la empresa**. Él conoce las opciones disponibles y decide *cuál* pedir para resolver tu encargo — pero quien finalmente **aprieta el botón** eres tú (tu código). El empleado no ejecuta nada por su cuenta: solicita, y tú autorizas o rechazas.

</Box>

<Box kind="analogy" label="◆ Primera vez que ves `@`: un decorador">

La línea `@tool` justo encima de un `def` es un **decorador**: envuelve tu función y le añade poderes sin que cambies su cuerpo. `@tool` toma la función normal de abajo y la registra como herramienta (leyendo su nombre, sus tipos y su docstring). Léelo como "convierte lo de abajo en una herramienta". En el curso solo necesitas *reconocer* el gesto, no escribir decoradores propios.

</Box>

```python title="functioncall.ipynb · una herramienta"
from langchain_core.tools import tool

@tool
def calculadora_descuentos(precio: float, porcentaje: float) -> float:
    """Calcula el precio final tras aplicar un descuento.
    Úsala cuando el usuario pida calcular precios con descuento."""
    return precio - (precio * porcentaje / 100)
```

```python title="07_herramientas.py · probarla e inspeccionar lo que ve el modelo"
# Pruébala como función normal, antes de dársela al modelo:
print("Precio final:", calculadora_descuentos.invoke({"precio": 3500, "porcentaje": 18}))

# Y mira lo que el modelo LEE para decidir cuándo y cómo usarla:
print("nombre      :", calculadora_descuentos.name)
print("descripción :", calculadora_descuentos.description)
print("parámetros  :", calculadora_descuentos.args)
```

```text title="▸ deberías ver"
Precio final: 2870.0
nombre      : calculadora_descuentos
descripción : Calcula el precio final tras aplicar un descuento.
    Úsala cuando el usuario pida calcular precios con descuento.
parámetros  : {'precio': {'title': 'Precio', 'type': 'number'}, 'porcentaje': {'title': 'Porcentaje', 'type': 'number'}}
```

<Box kind="warn" label="▲ Lección de oro">

El **docstring no es documentación: es programación**. El modelo decide *cuándo* usar la herramienta leyendo esa descripción, y usa los nombres/tipos de los parámetros (`precio: float`) para rellenar los datos. Docstring vago → agente que se equivoca.

</Box>

<Avoid label="⛔ Cuándo NO darle una herramienta al modelo">

- **Cuando la acción debe correr siempre.** Si un paso es obligatorio y determinista (guardar el pedido, cobrar), llámalo *tú* en el código. No lo dejes a criterio del modelo, que puede decidir no usarlo.
- **Cuando la acción es peligrosa sin control.** Borrar datos, mover dinero, mandar correos: exponerlas como tool sin una aprobación humana ([human-in-the-loop, m13](/modulo/13-langgraph-a-fondo)) es entregarle las llaves a algo que *pide* pero no entiende consecuencias.
- **Cuando hay demasiadas.** Una tool por cada capricho satura la elección: el modelo se confunde entre veinte casi-iguales. Menos herramientas, bien descritas, eligen mejor.

</Avoid>
