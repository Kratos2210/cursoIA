Toda cadena LCEL entiende los mismos verbos. No reescribes nada: es el mismo objeto `cadena`, tres formas de ejecutarlo.

<Box kind="def" label="◈ Definición · Interfaz unificada (Runnable)">

La **interfaz unificada** es el contrato que cumplen todas las piezas de LangChain: un prompt, un modelo, un parser y una cadena entera exponen *exactamente los mismos métodos*. Ese contrato tiene nombre: `Runnable`.

Es lo que hace posible el `|` del módulo anterior. Puedes conectar A con B porque ambos prometen entender los mismos verbos, y una cadena de dos Runnables **vuelve a ser un Runnable** — por eso las cadenas se anidan sin límite.

<DefList>
  <Term>invoke(entrada)</Term>
  <Def>Una entrada, una salida. El modo normal.</Def>
  <Term>batch([e1, e2, …])</Term>
  <Def>Muchas entradas **en paralelo**. No es un `for`: las llamadas salen a la vez, así que N preguntas tardan casi lo que una.</Def>
  <Term>stream(entrada)</Term>
  <Def>La salida llega por trozos según se genera, en vez de esperar al final. Es lo que hace que un chat "escriba" delante de ti.</Def>
  <Term>ainvoke / abatch / astream</Term>
  <Def>Los tres gemelos **asíncronos** (la `a` es de *async*): mismo comportamiento, pero liberan el programa mientras esperan a la API. Módulo 09.</Def>
</DefList>

</Box>

```python title="interfazunificada.ipynb · los 3 modos"
# 1) invoke: una entrada, una respuesta
cadena.invoke({"review": "Muy buena atención."})

# 2) batch: MUCHAS a la vez, en paralelo (rápido)
cadena.batch([
    {"review": "Me encantó, súper rápido."},
    {"review": "Pésima atención."},
])

# 3) stream: la respuesta llega por trozos, token a token
for trozo in cadena.stream({"review": "Cumple, nada especial."}):
    print(trozo, end="", flush=True)
```

```text title="▸ deberías ver (algo así — solo el stream imprime, y va apareciendo palabra a palabra)"
Neutro. La reseña describe una experiencia correcta pero sin entusiasmo.
```

<Box kind="analogy" label="◆ La versión asíncrona">

Cada verbo tiene su gemelo **async** con una `a` delante: `ainvoke`, `abatch`, `astream`. Sirven para no bloquear el programa mientras esperas a la API (lo profundizamos en el Módulo 09).

</Box>

```python title="versión async"
respuesta = await cadena.ainvoke({"review": "Excelente."})

async for trozo in cadena.astream({"review": "Excelente."}):
    print(trozo, end="", flush=True)
```

<Box kind="warn" label="▲ El await no va suelto">

`await` **solo funciona dentro de una función `async def`**. Si pegas `await cadena.ainvoke(...)` tal cual en un script normal, Python te lanza un `SyntaxError: 'await' outside function`. Para probarlo en un archivo, envuélvelo en una función async y arráncala con `asyncio.run(mi_funcion())` — justo como hace el Módulo 09. (En un notebook de Jupyter sí puedes escribir `await` a nivel de celda: el notebook ya corre dentro de un bucle async.)

</Box>

<Box kind="practice" label="▸ Para practicar">

Lee un CSV con `pandas`, conviértelo con `df.to_dict(orient="records")` y pásalo a `.batch()`. Cronometra `batch` vs un `for` con `invoke`: verás la diferencia.

<Solution summary="Ver una solución">

```python title="solución"
import time, pandas as pd

df = pd.read_csv("resenas.csv")            # una columna llamada "review"
filas = df.to_dict(orient="records")       # [{"review": "…"}, {"review": "…"}, …]

t = time.time()
cadena.batch(filas)
print("batch :", round(time.time() - t, 1), "s")

t = time.time()
for f in filas:
    cadena.invoke(f)
print("un for:", round(time.time() - t, 1), "s")   # bastante más lento
```

</Solution>
