El [c26](/concepto/26-mapa-del-ecosistema) te enseñó el mapa de frameworks y te mostró el **"sabor"** de otras APIs con snippets **que no se ejecutaban**. Este anexo los vuelve **ejecutables**: correr LlamaIndex y CrewAI de verdad fija mucho mejor la lección que solo leerlos. Y la lección no es "cuál es mejor", es **reconocer la misma idea con otra piel**.

<Box kind="warn" label="▲ Anexo opcional, fuera del 'offline-first'">

LlamaIndex y CrewAI son **ecosistemas propios** (no LangChain): muchas dependencias y una API de LLM con cuota. Por eso viven en `frameworks/` con extras opcionales (`uv sync --extra llamaindex` / `--extra crewai`) y **fuera** del gate offline — la CI no los instala ni los testea (`docs/adr/0006-frameworks-alternativos-fuera-del-gate.md`). Ambos apuntan al **mismo endpoint** del `.env` que ya usas. Es lectura si no tienes cuota.

</Box>

### LlamaIndex: el mismo RAG, con menos andamiaje

Lo que en el [c11](/concepto/11-rag-profesional) fueron varias piezas (loader → splitter → embeddings → vector store → recuperar → prompt) LlamaIndex lo resuelve en tres líneas. **"Los datos primero"**:

```python title="frameworks/rag_llamaindex.py · el núcleo"
documentos = SimpleDirectoryReader(input_files=[str(CORPUS)]).load_data()
indice = VectorStoreIndex.from_documents(documentos)   # trocea + indexa por ti
motor = indice.as_query_engine(similarity_top_k=3)     # recuperar + prompt + LLM
respuesta = motor.query("¿Cuál es el horario de atención?")
```

<Box kind="def" label="◈ ¿Es el mismo RAG del c11? Sí">

`as_query_engine` hace **recuperar + montar prompt + llamar al LLM** — exactamente el pipeline del c11. Lo que cambia es cuánto **ves y tocas**: aquí `from_documents` elige el troceado y el índice por ti. Menos código, menos control. El curso usa los **mismos embeddings fastembed locales** (sin cuota) para que el RAG no dependa de que tu proveedor de chat ofrezca embeddings.

</Box>

### CrewAI: describes roles, la "crew" coordina

El [c15](/concepto/15-multiagente-supervisor) armó el patrón supervisor con un `StateGraph` a mano. CrewAI sube el nivel: das **roles y tareas** y él encadena. Sin grafo, sin estado, sin aristas a la vista:

```python title="frameworks/crew_crewai.py · roles en vez de grafo"
investigador = Agent(role="Investigador", goal="Reunir 3 datos fiables", llm=llm, ...)
redactor     = Agent(role="Redactor", goal="Convertirlos en un párrafo", llm=llm, ...)
redactar = Task(description="...", agent=redactor, context=[investigar])  # recibe lo del investigador
Crew(agents=[...], tasks=[...], process=Process.sequential).kickoff()
```

<Box kind="analogy" label="◆ Furgoneta manual vs bus con conductor (del c26)">

LangGraph es la *furgoneta con caja manual*: ves cada marcha (nodo, arista, estado) y la metes tú. CrewAI es el *bus con conductor*: subes, dices el destino en roles y él coordina. Cómodo para prototipar rápido una colaboración legible; incómodo el día que necesites **auditar cada transición** — el alto nivel te esconde el volante.

</Box>

<Avoid label="⛔ La trampa de correr otro framework y sacar la conclusión equivocada">

- **Creer que "menos código" es "mejor".** Menos código es menos control. Para una demo, LlamaIndex/CrewAI vuelan; para producción auditable, el c15 en LangGraph te deja ver y testear cada paso.
- **Olvidar que la disciplina es tuya.** DI, `pytest -m offline` y observabilidad no vienen del framework (c26): los montas tú alrededor de casi cualquiera. No los pierdas al cambiar de piel.
- **Migrar por hype.** Cambiar de framework no es gratis: reescribes pegamento, tests y tracing. Corre estos para *entenderlos*, no para saltar sin motivo.

</Avoid>

<Box kind="practice" label="▸ Para practicar">

**Mini-reto** · haz visible lo que `from_documents` decide por ti. Corre `frameworks/rag_llamaindex.py` y `11_rag.py` con la **misma pregunta** sobre `datos_rag.txt`, y levanta una tabla de las decisiones del pipeline RAG marcando en cada framework si son **explícitas** (tú las escribes) u **ocultas** (el framework las eligió). Es lectura si no tienes cuota: la tabla sale del código, no de la ejecución.

**Criterio de aceptación:** identificas al menos cuatro decisiones —troceado, embeddings, cuántos fragmentos se recuperan y el prompt que envuelve el contexto— y para cada una nombras **dónde** se toma en cada framework: la línea del c11 o el default de LlamaIndex que la absorbe. Si una decisión no la encuentras en LlamaIndex, esa es exactamente la respuesta.

<Solution summary="Ver una solución">

| Decisión | En el c11 (LangChain) | En LlamaIndex | ¿Quién manda? |
| --- | --- | --- | --- |
| Troceado | `RecursiveCharacterTextSplitter(chunk_size=…, chunk_overlap=…)`, con los números a la vista | Dentro de `from_documents` — hay un default de chunking que no escribiste | Explícito vs **oculto** |
| Embeddings | El objeto que le pasas al vector store | `Settings.embed_model` (aquí, fastembed local para no depender de cuota) | Explícito en ambos — es config global vs argumento |
| Cuántos fragmentos | `search_kwargs={"k": 3}` en el retriever | `as_query_engine(similarity_top_k=3)` | Explícito en ambos |
| El prompt del RAG | Lo escribes tú: el `ChatPromptTemplate` con el contexto | Dentro del query engine — hay una plantilla por defecto que nunca ves | Explícito vs **oculto** |
| Postprocesado / re-ranking | Lo montas tú (c12) | `node_postprocessors`, opcional y también con defaults | Explícito vs opcional |

Las dos filas que importan son la primera y la cuarta: **el troceado y el prompt son las dos palancas que más mueven la calidad de un RAG**, y son justo las que `from_documents` + `as_query_engine` te esconden. No está mal —para una demo es una ventaja enorme—, pero explica el tradeoff del [c26](/concepto/26-mapa-del-ecosistema) mejor que cualquier tabla comparativa: el día que el RAG responda regular, en el c11 sabes qué tocar; aquí primero tienes que averiguar qué eligió el framework por ti.

Y el corolario honesto: LlamaIndex **también** te deja bajar (`node_parser`, `text_qa_template`). La diferencia no es que no puedas, es que el camino por defecto no te obliga a decidir — y lo que no decides, no lo mides.

</Solution>

</Box>
