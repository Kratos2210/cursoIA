Todo empieza con una llamada al modelo. Un chat model recibe **mensajes** y devuelve una **respuesta**. El método clave es `.invoke()`.

<Box kind="def" label="◈ Definición · Modelo de chat (chat model)">

Un **modelo de chat** es un LLM al que no le hablas con un texto suelto, sino con una **lista de mensajes con rol**, y que te devuelve un mensaje más. Toda la librería está construida sobre esa forma: mensajes entran, mensaje sale.

Esa es la diferencia con "un LLM" a secas. El LLM es el modelo entrenado; el *chat model* es la envoltura de LangChain que le da una interfaz uniforme (`.invoke()`, `.batch()`, `.stream()`) idéntica en Gemini, OpenAI o Claude.

<DefList>
  <Term>token</Term>
  <Def>La unidad en la que el modelo lee y escribe: un trozo de palabra (≈ 4 caracteres). No cuentas letras ni palabras, cuentas tokens — porque es lo que te cobran y lo que limita cuánto texto le cabe.</Def>
  <Term>ventana de contexto</Term>
  <Def>El máximo de tokens que el modelo puede tener "a la vista" en una llamada: pregunta + historial + documentos + su propia respuesta. Cuando se llena, algo hay que recortar.</Def>
  <Term>temperature</Term>
  <Def>Cuánta aleatoriedad se permite al elegir el siguiente token. `0` = la misma respuesta siempre; `0.9` = variada. No es "inteligencia", es dispersión.</Def>
</DefList>

</Box>

```python title="llmodel.py · primer contacto"
import os
from dotenv import load_dotenv
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_core.messages import HumanMessage

load_dotenv()  # lee el .env y carga tu llave (GOOGLE_API_KEY)

# El "cerebro". temperature=0 -> respuestas precisas y estables.
llm = ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite", temperature=0)

respuesta = llm.invoke([HumanMessage(content="Explica qué es un LLM en una frase.")])
print(respuesta.content)
```

<Box kind="analogy" label="◆ ¿Solo tienes llave de Groq? Cambia dos líneas">

Groq sirve modelos abiertos con un cupo gratuito mucho más generoso que el de Gemini. El resto del archivo —y del curso entero— es idéntico: `invoke`, los mensajes, las cadenas, los agentes. Solo cambia *quién* está al otro lado del cable.

El **ID del modelo caduca**: los proveedores retiran modelos varias veces al año (a `qwen/qwen3-32b`, el default anterior del curso, lo apagó Groq en 2026-07). Si te responde `model_decommissioned`, copia uno vigente de la [tabla de modelos del cheat sheet](/recurso/cheat-sheet) y ponlo en `LLM_MODELO` de tu `.env`.

```python title="llmodel.py · la misma idea, con Groq"
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI          # ← sirve para Groq, no solo para OpenAI
from langchain_core.messages import HumanMessage

load_dotenv()  # lee el .env y carga GROQ_API_KEY

llm = ChatOpenAI(
    model="openai/gpt-oss-120b",                 # ← el ID vigente a 2026-07-21
    temperature=0,
    base_url="https://api.groq.com/openai/v1",   # ← lo único específico de Groq
    api_key=os.getenv("GROQ_API_KEY"),
    # Este modelo RAZONA antes de responder. Los gpt-oss devuelven ese
    # razonamiento en un campo aparte (no ensucia el texto); esto lo apaga
    # para no pagar tokens que nadie va a leer.
    extra_body={"include_reasoning": False},
)

respuesta = llm.invoke([HumanMessage(content="Explica qué es un LLM en una frase.")])
print(respuesta.content)
```

Los ejemplos del repositorio no repiten esto diecinueve veces: llaman a `util.crear_llm()`, que lee `LLM_PROVIDER` del `.env` y devuelve el modelo correcto ya configurado. **Esa función es la razón por la que puedes cambiar de proveedor sin tocar código.**

### Los tipos de mensaje

Una conversación es una lista de mensajes con roles distintos. Entenderlos es clave para todo lo que sigue (memoria, tools, agentes):

- **SystemMessage**: las reglas y personalidad ("eres un tutor paciente").
- **HumanMessage**: lo que dice el usuario.
- **AIMessage**: lo que responde el modelo (aquí también viajan los `tool_calls`).
- **ToolMessage**: el resultado de ejecutar una herramienta (Concepto 08).

```python title="roles en acción"
from langchain_core.messages import SystemMessage, HumanMessage

mensajes = [
    SystemMessage(content="Eres un tutor paciente. Responde con ejemplos simples."),
    HumanMessage(content="¿Qué es un vector?"),
]
print(llm.invoke(mensajes).content)
```

<Box kind="def" label="◈ .content lee el texto; .content_blocks lee TODO (v1)">

`respuesta.content` te da el texto, y para empezar es lo único que necesitas. Pero una respuesta v1 puede traer más que texto —el **razonamiento** de un modelo que piensa, las **llamadas a herramientas**, trozos de **imagen**—. LangChain 1.x expone eso de forma uniforme en `respuesta.content_blocks`: una lista de bloques tipados que se lee **igual sea cual sea el proveedor**.

```python title="leer la respuesta por bloques (cross-provider)"
for bloque in respuesta.content_blocks:
    print(bloque["type"])   # "text", "reasoning", "tool_call", "image"…
```

Para texto plano, `.content` basta y lo verás en casi todo el curso. Cuando lleguemos a lo multimodal ([c22](/concepto/22-multimodal)) y al razonamiento, `content_blocks` es la forma correcta de leerlo sin depender del proveedor.

</Box>

<Box kind="analogy" label="◆ Bueno saber">

El parámetro `temperature` controla la creatividad: `0` = preciso y repetible (clasificar, calcular, usar tools); `0.7–1` = variado (redactar, conversar). Todo el curso usa `0` a propósito: así, si repites un ejemplo, obtienes lo mismo y puedes comparar.

</Box>

### El archivo `util.py` (lo vas a ver en todos los ejemplos)

Al clonar el repo te llevaste, junto a los ejemplos, un archivo llamado `util.py`. **No es una librería ni magia del curso**: es un `.py` corriente, en la misma carpeta que los ejemplos y que tus `mi_01.py`, y puedes abrirlo y leerlo — está comentado línea por línea. Eso es todo lo que hace falta para que esto funcione:

```python title="mi_01.py · usar la fábrica en vez de instanciar a mano"
from util import crear_llm

llm = crear_llm()          # lee LLM_PROVIDER del .env y devuelve el modelo ya configurado
print(llm.invoke("Explica qué es un LLM en una frase.").content)
```

Existe por una razón práctica: **22 ejemplos** del curso necesitan lo mismo (crear el modelo, reconocer un `429`, avisar si falta la llave). Repetir ese bloque en 22 archivos sería 22 sitios donde equivocarse. Además, al estar suelto en una función, esa lógica se puede **testear sin gastar cuota** — es lo que hace `tests/test_util.py`.

Dentro hay cuatro familias de funciones. No las memorices; te las irás encontrando:

| Familia | Funciones | Para qué |
| --- | --- | --- |
| La fábrica | `crear_llm()` · `crear_embeddings()` | construir el modelo que diga el `.env` |
| Las llaves | `requiere_llm_key()` · `cargar_var_entorno()` | fallar con un mensaje legible en vez de un traceback |
| La cuota | `es_error_cuota()` · `mensaje_cuota()` | reconocer el `429` y explicarlo ([c09](/concepto/09-resiliencia-async)) |
| El texto | `trocear_parrafos()` | partir documentos en fragmentos (lo usa el RAG del [c11](/concepto/11-rag-profesional)) |

Y ya que estás mirando la carpeta: hay **tres archivos `.py` que no son ejemplos**, y conviene no confundirlos.

| Archivo | ¿Es tuyo? | Para qué |
| --- | --- | --- |
| `util.py` | lo usas | lo importan los ejemplos; es el de esta sección |
| `env_utils.py` | lo corres | tu chequeo de entorno del día 1 ([c00](/concepto/00-preparar-el-terreno)) |
| `verificar_curso.py` | ignóralo | es del mantenedor: comprueba que el material sea coherente |

<Box kind="def" label="◈ ¿Y por qué no `init_chat_model`?">

LangChain 1.x trae su propio atajo, `init_chat_model("proveedor:modelo")` — por ejemplo `init_chat_model("openai:gpt-5.4-mini")` o `init_chat_model("anthropic:claude-haiku-4-5")`. Es la sintaxis canónica y está muy bien. ¿Por qué el curso no la usa?

**Para unos proveedores daría igual; para otros, no.** `crear_llm()` tiene dos ramas:

- **Gemini y Claude** son los dos únicos que *no* hablan el dialecto de OpenAI, así que tienen su clase propia. Ahí `init_chat_model` haría exactamente lo mismo, ni mejor ni peor.
- **Los otros seis** (OpenAI, Groq, Ollama, OpenRouter, DeepSeek, Kimi) sí lo hablan, y se resuelven con **un solo `ChatOpenAI` cambiando la `base_url`** — como viste arriba con Groq. Ahí es donde `init_chat_model` se queda corto, por dos motivos.

**Motivo 1: no es un cliente único, es un despachador.** `"groq:…"` no habla con Groq: importa `langchain_groq`, un paquete aparte. Cubrir los ocho proveedores del curso costaría cuatro paquetes más… y Kimi se quedaría fuera igual, porque ni siquiera está en su lista.

**Motivo 2: cada proveedor tiene sus parámetros prohibidos**, y mandarles el equivocado no da un aviso: da un error 400. `crear_llm()` los conoce:

- **Groq** solo acepta el formato de salida estructurada del [c05](/concepto/05-salida-estructurada) en *algunos* modelos; en el resto hay que pedirlo por otro camino.
- **El razonamiento** se oculta con un parámetro distinto en Groq, en la familia `gpt-oss` y en OpenRouter — y son mutuamente excluyentes.
- **Kimi prohíbe `temperature`**, justo el que este curso fija en `0` en todas partes.

Se ve mejor con las dos ramas juntas. Primero, con el atajo de LangChain:

```python title="con init_chat_model · un proveedor nativo y otro compatible"
from langchain.chat_models import init_chat_model

# ── Gemini (nativo) · aquí el atajo va perfecto ─────────────────
llm = init_chat_model("google_genai:gemini-3.1-flash-lite", temperature=0)

# ── Groq (compatible con OpenAI) · el mismo atajo ya no basta ───
llm = init_chat_model(
    "openai/gpt-oss-120b",
    model_provider="openai",                      # ChatOpenAI, para no instalar
    temperature=0,                                # un paquete por proveedor
    base_url="https://api.groq.com/openai/v1",    # la URL de Groq
    api_key=os.getenv("GROQ_API_KEY"),            # su llave, con OTRO nombre
    extra_body={"include_reasoning": False},      # parámetro propio de gpt-oss:
)                                                 # otro modelo pide otro distinto

datos = llm.with_structured_output(Ficha, method="function_calling")
#                                         ↑ hay que acordarse en CADA llamada del c05
```

Y ahora lo mismo con la fábrica del curso — **las dos ramas se escriben igual**:

```python title="con crear_llm() · idéntico para los ocho proveedores"
from util import crear_llm

llm = crear_llm()                           # proveedor, modelo, llave y parches: del .env
datos = llm.with_structured_output(Ficha)   # ya entra por el camino que aguanta
```

```ini title=".env · lo único que cambias para saltar de rama"
LLM_PROVIDER=google      # …o groq, anthropic, ollama, openrouter, deepseek
```

La diferencia no es cuántas líneas escribes: es **dónde vive el conocimiento de cada proveedor**. Arriba está repartido por tu código, así que cambiar de proveedor es editarlo (y si te dejas puesto el `extra_body` de Groq al pasar a Gemini, es un 400). Abajo vive en un solo sitio, y cambiar de proveedor es una línea del `.env` — que es justo lo que necesitas la tarde en que se te agota la cuota a mitad de ejercicio.

**Y esto no es un apaño del curso.** Apuntar un cliente de OpenAI a otra `base_url` es lo que documentan los propios proveedores — es la razón por la que anuncian ser "compatibles con OpenAI" —, y una fábrica que lee configuración y devuelve el cliente correcto es el mismo patrón que hay detrás de un *gateway* (LiteLLM, OpenRouter, Bedrock).

Así que `init_chat_model` no es peor: **resuelve otro problema**. Sirve para elegir modelo por nombre en una app que se queda en un proveedor. Este curso salta de proveedor en cuanto se te agota la cuota, y ahí es donde aparecen los casos de arriba. El detalle de cada uno, en el [c18b](/concepto/18b-elegir-modelo-y-proveedor).

</Box>
