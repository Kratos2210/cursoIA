Durante 26 conceptos usaste el modelo como una **caja negra**: texto entra, texto sale. Este concepto la abre. No para que entrenes uno —eso son millones de dólares en GPUs— sino para que entiendas las piezas que explican *todo* lo que ya viste: por qué `temperature=0` es determinista, por qué se paga por token, por qué el modelo a veces "alucina" con seguridad. Y como en el resto del curso, cada pieza es una **función pura** que puedes testear byte a byte.

<Box kind="def" label="◈ El árbol al que pertenece un LLM">

Cada término es un subconjunto del anterior: **IA** (máquinas que imitan conducta inteligente) ⊃ **Machine Learning** (aprenden patrones de los datos, no de reglas escritas a mano) ⊃ **Deep Learning** (redes neuronales de muchas capas) ⊃ **IA Generativa** (crean contenido nuevo, no solo clasifican) ⊃ **LLM** (generativa especializada en texto). Cuando alguien dice "la IA", casi siempre habla de la última rama de este árbol.

</Box>

<Box kind="def" label="◈ Definición · las cinco piezas, una frase cada una">

<DefList>
  <Term>Token</Term>
  <Def>El modelo no lee letras ni palabras, sino **trozos de palabra** (tokens). "proyectos" se parte en más tokens que "proyecto": por eso el plural cuesta un poco más.</Def>
  <Term>Logits + softmax</Term>
  <Def>Para cada token posible el modelo emite un **logit** (puntaje crudo); **softmax** los vuelve probabilidades que suman 1.</Def>
  <Term>Temperatura</Term>
  <Def>Modula esa distribución antes de elegir: **t→0** la concentra (determinista, "greedy"); **t alta** la aplana (más azar).</Def>
  <Term>Muestreo (top_k / top_p)</Term>
  <Def>Cómo se saca **una** palabra sin caer siempre en la más probable ni en cualquier disparate: recortando la distribución a los mejores candidatos.</Def>
  <Term>Perplejidad</Term>
  <Def>"Qué tan **sorprendido**" quedó el modelo por un texto. Baja = lo esperaba (fluido); alta = tuvo que apostar por tokens improbables.</Def>
</DefList>

</Box>

<Box kind="analogy" label="◆ El modelo como un autocompletar con dado cargado">

Imagina el teclado del móvil que sugiere la siguiente palabra, pero a lo bestia. En cada paso arma una lista de candidatos con un peso cada uno (los **logits**). La **temperatura** decide si tiras un dado muy cargado hacia el favorito (t baja, siempre lo mismo) o un dado casi justo (t alta, sorpresas). **top_k/top_p** es tapar del dado las caras absurdas antes de tirarlo. Y la **perplejidad** es cuánto te chocó la palabra que de verdad salió.

</Box>

### Tokenización · por qué el plural cuesta un token más

BPE (*Byte-Pair Encoding*) parte de caracteres sueltos y, repetidamente, **fusiona el par adyacente más frecuente** en un token nuevo. Así los trozos que aparecen mucho ("proyect", "to") se vuelven una pieza y los raros quedan partidos. Es —simplificado— lo que hacen GPT, Gemini o Claude por dentro.

```python title="curso_ejemplos/27_fundamentos_llm.py · tokenizar_bpe (aplica las fusiones aprendidas)"
def tokenizar_bpe(palabra, merges):
    secuencia = list(palabra)           # empieza en caracteres sueltos
    for a, b in merges:                 # aplica cada fusión EN ORDEN
        secuencia = _aplicar_merge(secuencia, a, b)
    return secuencia
```

Una palabra nueva reutiliza los trozos que quepan; lo que no encaje se queda en piezas pequeñas. Por eso `"proyectos"` = `['p','r','o','y','ecto','s']` cuesta un token **más** que `"proyecto"` = `['p','r','o','y','ecto']`: la `s` del plural no estaba en el vocabulario y viaja suelta. Multiplica eso por millones de palabras y entiendes por qué la factura del [c16](/concepto/16-observabilidad-y-costo) se cuenta en tokens, no en caracteres.

### Softmax con temperatura · qué hace de verdad `temperature=0`

```python title="curso_ejemplos/27_fundamentos_llm.py · softmax_con_temperatura (función pura)"
def softmax_con_temperatura(logits, t):
    if t <= 0:                          # límite t→0: toda la masa en el mayor
        i = max(range(len(logits)), key=lambda i: logits[i])
        return [1.0 if j == i else 0.0 for j in range(len(logits))]
    escalados = [x / t for x in logits] # t baja agranda las diferencias
    tope = max(escalados)               # restar el máximo evita desbordar exp()
    exp = [math.exp(x - tope) for x in escalados]
    suma = sum(exp)
    return [e / suma for e in exp]
```

Aquí está el mito desmontado: el modelo **no "elige" una palabra**. Produce un logit por token y softmax los vuelve probabilidades. `temperature=0` del [c01](/concepto/01-tu-primer-modelo) no "apaga la creatividad": pone toda la probabilidad en el token de mayor logit (*greedy*), por eso sale siempre lo mismo. Subir la temperatura aplana la distribución y da paso al azar —y al riesgo de disparate.

### Muestreo · sacar una palabra sin caer siempre en la más probable

Elegir siempre el favorito hace el texto plano; muestrear de toda la distribución deja pasar tonterías improbables. Los dos recortes de siempre: **top_k** (los k mejores) y **top_p** (el menor grupo que suma probabilidad p, el "núcleo"). Se muestrea con un `random.Random(semilla)` **inyectado**: misma semilla, misma salida, así el azar se puede testear.

```text title="▸ deberías ver al correr uv run python 27_fundamentos_llm.py"
[1] TOKENIZACIÓN (BPE) · el modelo lee trozos, no palabras:
    'proyecto'  → ['p', 'r', 'o', 'y', 'ecto']  (5 tokens)
    'proyectos' → ['p', 'r', 'o', 'y', 'ecto', 's']  (6 tokens)

[2] SOFTMAX CON TEMPERATURA · sobre logits [2.0, 1.0, 0.2, -1.0]
    t=0.5 (fría)    : [0.858, 0.116, 0.023, 0.002]  ← se concentra
    t=2.0 (caliente): [0.447, 0.271, 0.182, 0.1]    ← se aplana

[4] PERPLEJIDAD · exp(-media de log-prob):
    texto fluido  → 1.15   (baja = no sorprende)
    texto basura  → 18.80  (alta = sospechoso, ver c28)
```

### Perplejidad · "qué tan sorprendido está el modelo"

Es `exp(-media de log-probabilidades)` de los tokens que *realmente* aparecieron. Si a un texto fluido el modelo le asignó probabilidades altas, la perplejidad es baja ("esto lo esperaba"); si tuvo que apostar por tokens que creía improbables, se dispara. Es la métrica clásica de fluidez —y en el concepto siguiente (**c28**) reaparece como **defensa**: un prompt adversarial o basura tiene tokens improbables → perplejidad alta → un filtro puede marcarlo como sospechoso antes de que llegue al modelo.

### Atención · a qué palabras mira cada palabra

La idea que hizo posible el transformer, sin frameworks: cada palabra pregunta "¿con cuáles de las demás me relaciono?". La afinidad es el **producto punto** entre su vector-consulta y el vector-clave de cada palabra (el mismo producto punto del coseno del [c12](/concepto/12-recuperar-re-rankear)); softmax lo vuelve un reparto de atención que suma 1. Así "el banco de la plaza" y "el banco me cobró" desambiguan: "banco" mira a palabras distintas en cada frase.

La otra mitad —de dónde salió el transformer (Markov → RNN → atención), las familias encoder/decoder, cómo se alinea un modelo (RLHF/DPO) y qué lo hace rápido y barato (KV cache, cuantización, MoE)— vive en el [c27b · Arquitecturas e historia](/concepto/27b-arquitecturas-e-historia). Aquí cerramos con dos avisos sobre lo que *no* arreglan los parámetros de muestreo.

</Box>

<Box kind="warn" label="▲ Saber esto NO reemplaza medir">

Entender los internos es cultura útil, pero cuidado con dos trampas. Una: **subir la temperatura no arregla un prompt malo** —solo añade azar. Dos: **bajar `top_p` no arregla una alucinación** —si el modelo no tiene el dato, muestrear con más cuidado no lo inventa; lo que necesitas es grounding con RAG ([c11](/concepto/11-rag-profesional)). Los parámetros de muestreo se tocan al final, cuando el prompt y el contexto ya están bien.

</Box>

<Avoid label="⛔ Cuándo NO te sirve abrir la caja">

- No te pongas a **optimizar `top_k`/`top_p`** antes de arreglar el prompt y el contexto: es pulir la última milla cuando el problema está tres pasos atrás.
- No confundas **determinismo con verdad**: `temperature=0` da la MISMA respuesta siempre, no la CORRECTA. Un modelo puede equivocarse igual de fijo.

</Avoid>

<Box kind="practice" label="▸ Para practicar">

Corre `uv run python 27_fundamentos_llm.py` y juega con los logits: cambia `[2.0, 1.0, 0.2, -1.0]` por valores más parecidos entre sí y mira cómo softmax reparte casi por igual (el modelo "duda"). Luego calcula la perplejidad de una lista de probabilidades altas y otra de bajas y comprueba el salto. Cuando llegues al **c28**, ese mismo `calcular_perplejidad()` será la base de un filtro que detecta prompts sospechosos.

**Mini-reto** · escribe `margen_de_confianza(logits, t)`: una función pura que devuelva cuánto le saca el token más probable al segundo, usando `softmax_con_temperatura`. Es la forma de *medir* —no de intuir— lo que la temperatura le hace a la distribución.

**Criterio de aceptación:** con `logits = [2.0, 1.0, 0.2, -1.0]`, el margen baja al subir la temperatura (`t=0.5` > `t=1.0` > `t=2.0`) y vale exactamente `1.0` con `t=0` (toda la masa en un token: greedy).

<Solution summary="Ver una solución">

```python title="solución · medir el efecto de la temperatura"
from importlib import import_module
c27 = import_module("27_fundamentos_llm")   # el archivo empieza por dígito

def margen_de_confianza(logits, t):
    probs = sorted(c27.softmax_con_temperatura(logits, t), reverse=True)
    if len(probs) < 2:
        return 1.0                          # un solo candidato: no hay competencia
    return probs[0] - probs[1]              # cuánto le saca el favorito al segundo

logits = [2.0, 1.0, 0.2, -1.0]
for t in (0, 0.5, 1.0, 2.0):
    print(f"t={t}: margen={margen_de_confianza(logits, t):.3f}")
# t=0   : 1.000  ← greedy, el favorito se lleva TODA la probabilidad
# t=0.5 : 0.742  ← distribución concentrada, el favorito domina
# t=1.0 : 0.399
# t=2.0 : 0.176  ← aplanada: el segundo casi empata → más azar al muestrear

# El test que lo fija (los números exactos dependen de los logits; el ORDEN no):
assert margen_de_confianza(logits, 0) == 1.0
assert (margen_de_confianza(logits, 0.5)
        > margen_de_confianza(logits, 1.0)
        > margen_de_confianza(logits, 2.0))
```

Ojo con la conclusión: un margen alto dice que el modelo está **seguro**, no que tenga **razón**. Es la misma trampa del `temperature=0` — determinismo no es verdad.

</Solution>
