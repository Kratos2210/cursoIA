Un LLM puede afirmar con total aplomo algo **falso**: eso es una **alucinación**. No es un bug que se "arregla" de una vez —es consecuencia de cómo funciona (el [c27](/concepto/27-fundamentos-del-llm) lo explicó: predice el siguiente token, no consulta la verdad)—. Lo que SÍ puedes es entender de dónde vienen y montar defensas. Este es un concepto **integrador**: cada desafío se conecta con la mitigación que ya practicaste, y añade dos detectores nuevos y medibles.

<Box kind="def" label="◈ El paraguas · los cuatro grandes desafíos de un LLM">

La teoría los agrupa en cuatro familias; este concepto abre la que más muerde en producción, la **técnica**: la alucinación.

<DefList>
  <Term>De datos</Term>
  <Def>Sesgo, conocimiento desactualizado, dependencia de la calidad del corpus.</Def>
  <Term>Éticos y sociales</Term>

  <Term>De despliegue</Term>

</DefList>

</Box>

<Box kind="analogy" label="◆ El estudiante que nunca dice ”no sé”">

Un LLM es como un alumno brillante al que **penalizan por quedarse callado**: siempre contesta algo, aunque no lo sepa, y lo hace con la misma seguridad que cuando sí lo sabe. El truco para pillarlo: **pregúntale lo mismo varias veces**. Si lo sabe, repite la misma respuesta; si lo está inventando, cada vez dice algo distinto. Esa *dispersión* es la señal de alarma —y es exactamente lo que mide el detector de este concepto.

</Box>

### Detectar la inconsistencia · el reverso del self-consistency

En el [c26b](/concepto/26b-prompt-engineering), ante varias muestras de la misma pregunta, **votabas la moda** para acertar más. Aquí usamos las mismas muestras al revés: **medimos cuánto discrepan**. Poca dispersión = el modelo sabe; mucha = probablemente inventa. Es la idea de **SelfCheckGPT** reducida a aritmética testeable.

```python title="28_alucinaciones.py · detectar_inconsistencia (función pura)"
from collections import Counter

def detectar_inconsistencia(respuestas):
    # respuestas cortas ya extraídas ("París", "1812"), como el voto del c26b.
    if not respuestas:
        return 0.0
    normalizadas = [_normalizar(r) for r in respuestas]   # sin puntuación ni caja
    mas_comun = Counter(normalizadas).most_common(1)[0][1]
    return 1 - mas_comun / len(normalizadas)   # 0 = todas iguales; →1 = todas distintas
```

```text title="▸ deberías ver al correr uv run python 28_alucinaciones.py (recortado)"
[2] DETECTAR INCONSISTENCIA (estilo SelfCheckGPT):
    modelo que SABE     ['París', 'parís', 'París.']
       → divergencia 0.00  · ¿sospechosa? False
    modelo que INVENTA  ['1812', '1798', '1820', '1805']
       → divergencia 0.75  · ¿sospechosa? True
```

El acompañante es `medir_fragilidad()`: si cambiar una coma o un sinónimo en el prompt cambia la respuesta, el resultado dependía de la **forma**, no del conocimiento —una alerta distinta pero pariente.

<Box kind="def" label="◈ Defensas de entrada · el filtro de perplejidad y SmoothLLM">

Dos ideas de investigación que cierran el círculo con conceptos anteriores. El **filtro de perplejidad** reusa el `calcular_perplejidad()` del [c27](/concepto/27-fundamentos-del-llm): un prompt adversarial suele ser texto "raro" con tokens improbables → perplejidad alta → se marca antes de llegar al modelo. Y **SmoothLLM** hace varias copias del prompt con perturbaciones mínimas y compara las salidas: si un carácter de más tumba el ataque, es que era frágil y malicioso. Ambas son baratas y se apilan sobre los guardarraíles del [c23](/concepto/23-seguridad-red-teaming).

</Box>

<Box kind="warn" label="▲ Un detector no es una garantía">

La divergencia baja significa "el modelo es **consistente**", no "el modelo tiene **razón**": puede equivocarse igual de firme las tres veces (un sesgo del entrenamiento no se disipa muestreando). El detector sube una *bandera de sospecha* cuando hay dispersión; la verdad se establece con **grounding** (RAG) y **evaluación** (un dataset con respuestas de referencia), no con estadística sobre las propias muestras del modelo.

</Box>

<Avoid label="⛔ Cuándo NO aplicar esto">

- No corras el detector en tareas **creativas** (redactar, parafrasear): ahí la variedad entre muestras es deseable, no una alucinación.
- No pagues **N muestras** para cada consulta trivial: el muestreo múltiple multiplica el coste; resérvalo para respuestas factuales de alto riesgo.
- No confundas **consistente** con **correcto**: sin una fuente o un dataset, un modelo puede estar seguro y equivocado a la vez.

</Avoid>

**Mini-reto** · monta el **filtro de perplejidad** del que habla la caja de arriba: `es_prompt_sospechoso(probabilidades, umbral=10.0)`, reusando `calcular_perplejidad()` del [c27](/concepto/27-fundamentos-del-llm). Es una defensa de **entrada**: corre antes de gastar un token de LLM.

**Criterio de aceptación:** el texto fluido del c27 (`[0.9, 0.85, 0.8, 0.92]`, perplejidad 1.15) pasa como limpio; la basura (`[0.05, 0.1, 0.02, 0.08]`, perplejidad 18.80) se marca; y una lista **vacía** también se marca (perplejidad `inf` — la ausencia de señal no es señal de inocencia).

<Solution summary="Ver una solución">

```python title="solución · defensa de entrada barata, antes de llamar al modelo"
from importlib import import_module
c27 = import_module("27_fundamentos_llm")   # los archivos empiezan por dígito

def es_prompt_sospechoso(probabilidades, umbral=10.0):
    # calcular_perplejidad ya devuelve inf con lista vacía o alguna prob <= 0,
    # así que el caso degenerado cae del lado seguro sin un if extra.
    return c27.calcular_perplejidad(probabilidades) >= umbral

fluido = [0.9, 0.85, 0.8, 0.92]     # perplejidad 1.15
basura = [0.05, 0.1, 0.02, 0.08]    # perplejidad 18.80

assert es_prompt_sospechoso(fluido) is False
assert es_prompt_sospechoso(basura) is True
assert es_prompt_sospechoso([]) is True          # inf >= umbral → se marca
```

Dos avisos antes de llevarlo a producción. Uno: el **umbral se calibra con datos tuyos**, no se copia — texto técnico, código o jerga tienen perplejidad naturalmente alta y te llenarían de falsos positivos. Dos: esto marca texto *raro*, no texto *malicioso*; un ataque escrito en español impecable pasa el filtro. Por eso se **apila** sobre los guardarraíles del [c23](/concepto/23-seguridad-red-teaming), no los sustituye.

</Solution>
