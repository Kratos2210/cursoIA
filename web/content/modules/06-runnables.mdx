Hasta ahora tus cadenas eran una línea recta. Estos tres "conectores" te dejan armar flujos con ramas y funciones propias — la base para el RAG del Nivel Avanzado.

<Box kind="def" label="◈ Definición · Runnable">

Un **Runnable** es *cualquier* pieza que se puede meter en una cadena LCEL: un prompt, un modelo, un parser, una función tuya, o una cadena entera. Solo tiene que cumplir el contrato del Módulo 03 (`invoke`, `batch`, `stream`).

La propiedad que lo vuelve poderoso es que **es cerrado bajo composición**: si `a` y `b` son Runnables, `a | b` también lo es. Por eso puedes tratar un RAG completo como si fuera un solo eslabón dentro de una cadena más grande.

<DefList>
  <Term>RunnableParallel</Term>
  <Def>Ejecuta varias ramas **a la vez** sobre la misma entrada y devuelve un diccionario con la salida de cada una. Un diccionario de Python dentro de una cadena ya se interpreta como esto.</Def>
  <Term>RunnablePassthrough</Term>
  <Def>El **cable**: deja pasar la entrada tal cual. Sirve para conservar el dato original mientras otra rama lo transforma (el patrón `{"contexto": retriever, "pregunta": passthrough}` del RAG).</Def>
  <Term>RunnableLambda</Term>
  <Def>Convierte **una función normal de Python** en un eslabón de la cadena. Es la puerta por la que entra tu propio código: limpiar, filtrar, formatear.</Def>
</DefList>

</Box>

<Grid3>

<Card num="" title="RunnableParallel">

Corre varias ramas *a la vez* y junta sus salidas en un diccionario.

</Card>

<Card num="" title="RunnablePassthrough">

Pasa la entrada tal cual, sin tocarla (clave en RAG para conservar la pregunta).

</Card>

<Card num="" title="RunnableLambda">

Mete cualquier función de Python dentro de la cadena.

</Card>

</Grid3>

<Box kind="analogy" label="◆ Primera vez que ves `lambda`: una función sin nombre">

`lambda x: x.upper()` es una función de una sola línea escrita *en el sitio*, sin `def` ni nombre. Equivale a `def f(x): return x.upper()`. Se usa cuando la función es tan corta que ponerle nombre estorba — justo lo que pide `RunnableLambda` para colar un paso propio dentro de la cadena.

</Box>

```python title="chaincompleja.ipynb · componer flujos"
from langchain_core.runnables import RunnableParallel, RunnablePassthrough, RunnableLambda
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from util import crear_llm

llm = crear_llm()
# Dos prompts, cada uno pide una cosa distinta sobre el MISMO {texto}
prompt_resumen     = ChatPromptTemplate.from_template("Resume en 5 palabras: {texto}")
prompt_sentimiento = ChatPromptTemplate.from_template("Sentimiento en 1 palabra de: {texto}")

# Dos análisis del mismo texto, en paralelo
analisis = RunnableParallel(
    resumen     = prompt_resumen     | llm | StrOutputParser(),
    sentimiento = prompt_sentimiento | llm | StrOutputParser(),
)
print(analisis.invoke({"texto": "El servicio fue rápido pero caro."}))

# Una función normal como eslabón de la cadena
a_mayusculas = RunnableLambda(lambda x: x.upper())
print((a_mayusculas).invoke("hola"))   # -> HOLA
```

```text title="▸ deberías ver (algo así)"
{'resumen': 'El cliente valoró la rapidez pero le pareció caro.', 'sentimiento': 'Neutro'}
HOLA
```

<Box kind="analogy" label="◆ Por qué importa">

Una cadena RAG (Módulo 11) es literalmente esto: `{"context": retriever | unir, "question": RunnablePassthrough()}`. Recuperas contexto en una rama y conservas la pregunta en la otra, en paralelo.

</Box>

<Avoid label="⛔ Cuándo NO usar estos runnables">

- **Cuando el flujo es una línea recta.** Si no hay ramas ni copias que conservar, un simple `prompt | llm | parser` sobra: meter `RunnableParallel` "por si acaso" solo añade indirección.
- **Cuando el paso hace algo caro o con efectos.** Un `RunnableLambda` es para lógica trivial y pura (limpiar, formatear, contar). Si la función llama a una API, escribe en disco o puede fallar, merece ser una herramienta ([m07](/modulo/07-herramientas)) o un nodo de grafo ([m13](/modulo/13-langgraph-a-fondo)), no un lambda escondido en la cadena.
- **Cuando la decisión es del modelo, no tuya.** Si el camino depende de lo que el modelo elija, eso es *routing* ([m08](/modulo/08-routing)) o un agente, no ramas fijas en paralelo.

</Avoid>

<Box kind="practice" label="▸ Para practicar">

Arma un `RunnableParallel` que a la vez traduzca un texto y cuente sus palabras (con un `RunnableLambda`). Observa el diccionario resultante.

<Solution summary="Ver una solución">

```python title="solución"
prompt_en = ChatPromptTemplate.from_template("Traduce al inglés: {texto}")

analisis = RunnableParallel(
    ingles   = prompt_en | llm | StrOutputParser(),          # rama 1: la IA traduce
    palabras = RunnableLambda(lambda x: len(x["texto"].split())),  # rama 2: Python cuenta
)
print(analisis.invoke({"texto": "La automatización ahorra tiempo valioso"}))
# {'ingles': 'Automation saves valuable time', 'palabras': 5}
```

</Solution>
