### Glosario rápido

| Término | En una frase |
| --- | --- |
| LLM | El modelo de lenguaje (Gemini, Qwen): conversa y razona. |
| Chat model | La envoltura de LangChain sobre un LLM: recibe mensajes con rol, devuelve un mensaje. |
| Token | El "trocito" de texto (≈¾ de palabra) que el modelo procesa y cobra. |
| Ventana de contexto | Máximo de tokens visibles en una llamada: prompt + historial + documentos + respuesta. |
| Temperature | Cuánta aleatoriedad se permite al generar: 0 = repetible; 0.9 = variado. |
| LCEL | Lenguaje declarativo de LangChain: conectar pasos con `\|` para formar una cadena. |
| Prompt template | Molde de instrucciones con huecos `{variables}`, reutilizable. |
| Output parser | Convierte la respuesta cruda del modelo en algo usable (texto, JSON, objeto). |
| Interfaz unificada | Todas las piezas entienden `invoke` / `batch` / `stream` (y sus gemelos async). |
| Salida estructurada | Forzar al modelo a devolver datos con un molde Pydantic. |
| Runnable | Cualquier pieza de una cadena LCEL (prompt, modelo, función…). |
| Memoria | El historial que *tú* reenvías en cada turno; el modelo no guarda nada. |
| MessagesPlaceholder | El hueco del prompt donde se inyecta ese historial. |
| Thread_id | La etiqueta que separa la conversación de un usuario de la de otro. |
| Tool | Función de Python que el modelo puede invocar solo. |
| Tool call | La *petición* del modelo (nombre + argumentos). Ejecutarla la decide tu código. |
| ToolMessage | El resultado que le devuelves al modelo; sin él, nunca ve qué pasó. |
| Routing | Dejar que el modelo elija el camino (responder o pedir una tool), en vez de un `if`. |
| ReAct | El ciclo del agente: razonar → actuar → observar → repetir. |
| Agente | Un LLM que repite pensar→actuar→observar hasta cumplir el objetivo. |
| Fallback | Modelo de respaldo si el principal falla (`with_fallbacks`). |
| Retry | Reintentar *lo mismo* ante fallos temporales (`with_retry`); inútil si el prompt está mal. |
| 429 | Error de cuota del proveedor. No es un bug de tu código. |
| Async / await | No acelera la llamada: libera el programa mientras espera a la API. |
| RAG | Buscar tus documentos y pegarlos como contexto antes de preguntar. Examen a libro abierto. |
| Retriever | La pieza que recibe la pregunta y devuelve los `k` chunks más relevantes. |
| Embedding | Huella numérica de un texto; parecidos → números parecidos. |
| Vector store | Base de datos que guarda embeddings y busca por parecido. |
| fastembed | Librería que ejecuta modelos de embeddings *en tu máquina*, sin API ni cuota. Usa ONNX Runtime en vez de PyTorch: ~70 MB en lugar de ~800 MB. |
| ONNX | *Open Neural Network Exchange*: formato estándar para guardar un modelo ya entrenado, independiente de la librería que lo entrenó. El "PDF de los modelos". |
| Inferencia | Usar un modelo ya entrenado para producir una salida. Lo contrario de *entrenamiento* (ajustar sus pesos). Casi todo lo que escribirás hace inferencia. |
| Open weights | Modelo cuyos pesos se descargan y puedes ejecutar tú (Llama, Qwen, DeepSeek). No es lo mismo que "open source": suele publicarse el modelo entrenado, no los datos ni el código de entrenamiento. Ver [Módulo 18b](/modulo/18b-elegir-modelo-y-proveedor). |
| Licencia de modelo | El contrato que dice qué puedes hacer con esos pesos. *Apache 2.0* (Qwen, DeepSeek) permite uso comercial libre; la *Llama Community License* pone restricciones. Revísala antes de construir un producto encima. |
| AWS Bedrock | Servicio que da acceso a modelos de varios proveedores *desde dentro de tu cuenta de AWS*: IAM y factura unificadas, y los datos no salen de tu VPC. Equivalentes: Vertex (GCP), Azure AI Foundry. Ver [Módulo 18b](/modulo/18b-elegir-modelo-y-proveedor). |
| vLLM | Servidor de inferencia para **producción** on-premise: con *continuous batching* exprime el throughput de una GPU para servir a muchos usuarios a la vez. Para desarrollo local, la herramienta cómoda es Ollama. |
| On-premise | Correr los pesos en *tu* hardware (portátil, servidor o datacenter): nada sale de tu red. Gana en privacidad y control; el coste no desaparece, se transforma en GPUs y operación. |
| OpenRouter | Agregador: UNA llave y un único endpoint hacia cientos de modelos de muchos proveedores, con variantes `:free` para prototipar. Habla el dialecto de OpenAI, así que en el curso es una `base_url` distinta. |
| Text splitter | Trocea documentos respetando frases/párrafos. |
| MMR | Recupera resultados relevantes y variados (evita duplicados). |
| Re-ranker | Segundo filtro que reordena y deja arriba lo más relevante. |
| Cross-encoder | Modelo que puntúa qué tan bien un fragmento responde a la pregunta. |
| Búsqueda híbrida | Combinar búsqueda por significado (denso) + por palabras (BM25). |
| BM25 | Algoritmo clásico de búsqueda por palabras exactas (premia las raras). |
| RRF | Fusionar dos rankings usando el puesto, no los puntajes. |
| Precision@k | De los k fragmentos recuperados, qué fracción era realmente útil. |
| Chunk | Cada fragmento en que se trocea un documento para indexarlo. |
| StateGraph | Grafo de estado de LangGraph: nodos + aristas (puede ser cíclico). |
| Arista condicional | Bifurcación del flujo según el estado (¿usar tool o terminar?). |
| Human-in-the-loop | Pausar el agente para que un humano apruebe (`interrupt`). |
| Checkpointer | La memoria del agente (RAM, SQLite o Postgres) por `thread_id`. |
| Supervisor | Nodo que no hace el trabajo: decide qué especialista lo hace. |
| Multiagente | Varios agentes especializados coordinados, en vez de uno que lo sabe todo. |
| Modelo falso | Modelo de mentira que recita un guion, para testear un agente sin API. |
| Log de auditoría | Registro escrito de cada transición y tool ejecutada (trazabilidad legal). |
| MCP | Estándar para conectar agentes con herramientas/datos externos. Convierte M×N integraciones en M+N. |
| Servidor MCP | Proceso que expone tools, resources y prompts de forma controlada. |
| Cliente MCP | El lado del agente: descubre lo que ofrece el servidor y lo traduce a tools. |
| Inyección de dependencias | Pasar modelo y retriever *por parámetro*; es lo que hace testeable el proyecto final. |
| Doble de prueba | Objeto que sustituye al modelo en los tests (ver *Modelo falso*). |
| Observabilidad | Ver qué hace el sistema en vivo (prompts, tools, tokens, tiempos) sin añadir código. |
| Microservicio | Componente independiente y desplegable por separado. |
| Contenedor | Paquete con tu código + sus dependencias, que corre igual en cualquier máquina. |
| Kubernetes | Orquestador declarativo: mantiene vivas N copias de cada servicio. |
| Balanceador de carga | Reparte el tráfico entre las copias vivas de un servicio. |
| Stateless | Servicio que no guarda estado propio: sus copias son intercambiables. |
| Serverless | Ejecutar funciones que escalan a cero; pagas por uso. |
| FastAPI | Librería de Python para exponer tu agente por HTTP, validando con Pydantic. |
| Endpoint | Una URL concreta de tu servidor (`POST /chat`) con su contrato de entrada y salida. |
| ASGI | El estándar que corre apps async de Python; `uvicorn` es quien lo implementa. |
| Cold start | La demora extra de la primera petición cuando una función serverless "despierta". |
| Latencia | Cuánto tarda una respuesta, de pregunta a texto final. |
| Throughput | Cuántas consultas por minuto aguanta el sistema sin degradarse. |
| Traza | El recorrido completo de una consulta: prompts, tools, tokens, costo. |
| LangSmith | Trazas, tokens y costos para depurar cada ejecución. |
| Arize | Monitoreo y evaluación de calidad en producción (Phoenix: su versión open-source). |
| LLM-as-judge | Usar otro modelo (temperatura 0) para calificar respuestas de texto libre. |
| Dataset de evaluación | Preguntas con respuesta esperada: la vara para medir calidad repetible. |
| Regresión | Algo que funcionaba se rompe tras un cambio; la evaluación la detecta. |
| ADR | Nota que documenta una decisión de arquitectura y su porqué. |
| Runbook | Manual de operación: cómo arrancar, qué vigilar, qué hacer si falla. |
| CI | Integración continua: tests + evaluación corren solos en cada cambio. |
| Agent engineering | El encuadre actual de LangChain: construir agentes como disciplina de ingeniería (con su ciclo de vida), no como demos sueltas. |
| Ciclo de vida del agente | Las cuatro etapas por las que pasa un agente en producción: Build → Test → Deploy → Monitor. |
| Deep Agents | Framework open source de LangChain para agentes de larga duración que resuelven tareas complejas (planifican e investigan por horas). |
| Agente ambiental | Agente que corre en segundo plano, disparado por eventos, y pide aprobación humana (`interrupt`) antes de una acción irreversible. Caso estrella: el asistente de correo. |
| Spec-Driven Development (SDD) | Escribir la especificación (QUÉ y POR QUÉ) antes del código; el spec es la fuente de verdad. Ver [Módulo 19](/modulo/19-spec-driven-development). |
| spec-kit | La herramienta que estructura el SDD en cinco pasos: constitution → /specify → /plan → /tasks → /implement. |
| Constitución (del proyecto) | Los principios no negociables del proyecto (aquí: español didáctico, `uv`, tests offline) que condicionan cada spec. |
