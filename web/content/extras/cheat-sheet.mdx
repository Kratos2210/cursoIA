### ¿Qué pieza uso para esta situación?

La tabla de arriba mapea intención → código. Esta mapea **situación de negocio → decisión**: cuando reconozcas tu caso en la primera columna, la segunda te dice qué sacar de la caja.

| Si tu situación es… | La pieza es… | Mód. |
| --- | --- | --- |
| Llegan cientos de reseñas o tickets al día y hay que clasificarlos igual | cadena LCEL + `batch` | 02·03 |
| El usuario pide algo en lenguaje libre y otro sistema consume el resultado | salida estructurada (Pydantic) | 05 |
| El dato vive en un sistema (stock, estado del pedido) y el modelo debe consultarlo | `@tool` + ciclo A→D | 07·08 |
| No sabes cuántos pasos tomará resolver la consulta | agente (con `recursion_limit`) | 10 |
| La respuesta debe salir de TUS documentos, citando la fuente | RAG (+ citación) | 11·20 |
| El usuario y el documento usan palabras distintas ("aros" / "aretes") | híbrida + re-rank / multi-query | 12·20 |
| La acción mueve dinero, firma o borra algo | `interrupt` (HITL) | 13 |
| Un solo agente se confunde entre sus doce herramientas | supervisor multiagente | 15 |
| La misma pregunta se repite mil veces al día | caché semántico (TTL + rol en la clave) | 16 |
| "Mejoré el prompt" tiene que dejar de ser una opinión | dataset + juez + gate | 16c |
| El dato cambia a diario (precios, stock, políticas) | RAG, jamás fine-tuning | 21·29 |
| Quieres fijar formato o tono y tienes cientos de ejemplos | LoRA (tras agotar few-shot) | 21·21b |
| Los datos no pueden salir de tu red o tu nube | on-premise / Bedrock·Vertex | 18b·34 |
| El proceso tiene reglas fijas y entrada de formato conocido | workflow determinista, sin LLM | 35 |

### Cambiar de proveedor (Gemini ↔ Groq ↔ OpenAI ↔ Claude)

**Nada** de lo que aprendiste depende del proveedor. El resto (LCEL, tools, agentes, RAG, grafos) queda intacto. De hecho los ejemplos del repo ya no instancian ningún modelo: llaman a `util.crear_llm()`, que lee `LLM_PROVIDER` del `.env`. Si prefieres el interruptor de LangChain, es `init_chat_model`:

```python title="el interruptor universal"
from langchain.chat_models import init_chat_model

# Sintaxis canónica v1: "proveedor:modelo".
llm = init_chat_model("google_genai:gemini-3.1-flash-lite")  # Google (GOOGLE_API_KEY)
# llm = init_chat_model("openai:gpt-5.4-mini")        # OpenAI  (OPENAI_API_KEY)
# llm = init_chat_model("anthropic:claude-haiku-4-5") # Anthropic (ANTHROPIC_API_KEY)

# Groq (y Ollama, y Together): NO hace falta una clase por proveedor.
# Todos hablan el dialecto de OpenAI; solo cambia la base_url.
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="openai/gpt-oss-120b",
                 base_url="https://api.groq.com/openai/v1",
                 api_key=os.getenv("GROQ_API_KEY"))
```

El conmutador de `util.crear_llm()` entiende estos `LLM_PROVIDER`; si no pones `LLM_MODELO`, usa el que trae cada uno de fábrica. Cuál elegir para una solución real (pago vs. open weights, precios, dónde corre) está en el [Concepto 18b](/concepto/18b-elegir-modelo-y-proveedor).

### Modelos vigentes: la tabla de copiar y pegar

<Box kind="warn" label="▲ ¿Un modelo se apagó? Se arregla en 30 segundos, sin tocar código">

Si tu proveedor responde `model not found`, `model_decommissioned` o `The model … has been deprecated`, **no es tu código**: retiraron ese modelo del catálogo. Es normal y pasa varias veces al año.

1. **Copia un ID vigente** de las tablas de aquí abajo (o directamente de la web oficial del proveedor, que siempre va por delante de nosotros).
2. **Pégalo en tu `.env`**:

```bash
LLM_MODELO=openai/gpt-oss-120b
```

Y ya. `LLM_MODELO` **gana sobre cualquier default del curso** (`util.modelo_por_defecto()` lo mira antes que su propia tabla), así que no tienes que esperar a que actualicemos el material. Ese es todo el sentido de que el modelo sea una variable de entorno y no una constante en el código.
