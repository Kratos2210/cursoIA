Todos los errores de esta tabla son **normales**: le pasan a cualquiera que sigue el curso. El hábito correcto (Módulo 0b): lee la *última línea* del traceback y búscala aquí.

| El error que ves | Qué significa | Qué hacer |
| --- | --- | --- |
| `429 RESOURCE_EXHAUSTED` | Se agotó la cuota del plan gratuito de Gemini. **No es un bug de tu código.** | Espera unos minutos, cambia a `gemini-2.5-flash`, o deja que actúen tus `with_fallbacks`/`with_retry` (Módulo 09). En los [ejercicios](/recurso/ejercicios), la salida buena es `LLM_PROVIDER=groq` + `GROQ_API_KEY`: pasan a `qwen/qwen3-32b` sin tocar código. |
| `ModuleNotFoundError: No module named 'langchain…'` | La librería no está instalada en el entorno con el que corres. | `uv pip install -r curso_ejemplos/requirements.txt` y ejecuta siempre con `uv run python …` (no con el Python del sistema). |
| `Creating virtual environment at: .venv` seguido de `ModuleNotFoundError` | Tu `pyproject.toml` tiene `dependencies = []`. Hiciste `uv init` pero no `uv add`: `uv run` instala **solo** lo declarado, y no había nada. | Corre los `uv add` del Módulo 00 dentro de tu carpeta. Si ya los corriste, estás parado en otra: comprueba con `pwd`. |
| El mismo comando funciona en una carpeta y falla en otra | `uv` elige el entorno según el `pyproject.toml` más cercano *hacia arriba*. Cambiar de carpeta cambia de `.venv`. | `uv run python -c "import sys; print(sys.prefix)"` te dice qué entorno usa de verdad. Haz `cd` al proyecto correcto. |
| "❌ Falta …_API_KEY" (`GOOGLE_API_KEY`, `GROQ_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY`…) | El `.env` no existe, está en otra carpeta, o pusiste la llave de un proveedor y `LLM_PROVIDER` apunta a otro. El mensaje siempre nombra **la variable del proveedor activo** — el único que `ollama` no necesita, porque corre en tu máquina. | Debe estar en `curso_ejemplos/.env`: `cp curso_ejemplos/.env.example curso_ejemplos/.env` y edítalo con la llave del proveedor que activaste. La lista completa y cómo elegir, en el [Módulo 18b](/modulo/18b-elegir-modelo-y-proveedor). |
| `400 API key not valid` | La llave se copió mal (espacios, comillas, incompleta) o fue revocada. | Regenérala en **aistudio.google.com**. En el `.env` va sin comillas y sin espacios: `GOOGLE_API_KEY=AIza…` |
| `401 Unauthorized` · `402 Payment Required` · `insufficient credits/quota` | Estás en un proveedor **de pago** (OpenAI, Anthropic, DeepSeek, o un modelo no `:free` de OpenRouter) y la cuenta no tiene saldo, no verificó facturación, o la llave no autoriza ese modelo. No es un bug del código: es la tarjeta, no el `.env`. | Carga saldo en la consola del proveedor, o cámbiate a una opción gratuita: `LLM_PROVIDER=groq`, `LLM_PROVIDER=google`, un modelo `:free` de OpenRouter, u `ollama` en tu máquina. Qué proveedor cobra y cuánto, en el [Módulo 18b](/modulo/18b-elegir-modelo-y-proveedor). |
| `command not found: uv` | `uv` no está instalado (o la terminal no lo encuentra). | Instálalo con `curl -LsSf https://astral.sh/uv/install.sh \| sh` y abre una terminal nueva. |
| `IndentationError` / `SyntaxError` | Al copiar, el código perdió su alineación (Módulo 0b: la indentación es sintaxis). | Usa el botón **copiar** de cada bloque de este curso y pega en un archivo vacío, sin retocar espacios. |
| `AttributeError: … has no attribute …` | Escribiste un nombre que no existe (típico: `.contenido` en vez de `.content`) o tu versión de librería cambió esa pieza. | Revisa la ortografía exacta; luego `uv pip list \| grep langchain` — el curso usa `langchain 1.x` y `langgraph 1.x`. |
| Pusiste `LLM_PROVIDER=groq` y aun así te pide `GOOGLE_API_KEY` | Estás corriendo un ejemplo de **RAG** (11, 12 o el proyecto final). El chat va por Groq, pero los **embeddings** siguen en Gemini: Groq no los ofrece. | `uv sync --extra emb` y añade `EMBEDDINGS_PROVIDER=fastembed` al `.env`: los calcula en tu máquina, sin cuota. Ver el Módulo 00. |
| Con Groq, las respuestas empiezan con `<think>…</think>` | `qwen3` es un modelo de razonamiento y Groq devuelve su cadena de pensamiento dentro del contenido. | Ya lo resuelve `util.crear_llm()` (`reasoning_format: hidden`). Si lo ves, es que instanciaste `ChatOpenAI` a mano. Para verlo a propósito: `GROQ_RAZONAMIENTO=raw`. |
| `400 · This model does not support response format json_schema` | `with_structured_output()` pide `json_schema`, y `qwen3-32b` no lo soporta en Groq. | Ya lo resuelve `util.crear_llm()` usando `method="function_calling"`. Si instancias el modelo a mano, pásale ese `method`. |
| `EMBEDDINGS_PROVIDER=fastembed` y falla con `No module named 'fastembed'` | El extra no está instalado. Va aparte porque descarga un modelo de ~220 MB. | `uv sync --extra emb`. Cambiar de modelo de embeddings **invalida cualquier índice ya construido**: hay que reindexar (en el curso da igual, se reconstruye en cada arranque). |
| `onnxruntime … doesn't have a … wheel for the current platform` (en `uv add` de `chroma`/`fastembed`) | Estás en un **Mac Intel** (`x86_64`). `chromadb` arrastra `onnxruntime`, que desde la **1.24** ya no publica binarios para esa plataforma. | En tu `pyproject.toml` añade `[tool.uv]` con `constraint-dependencies = ["onnxruntime<1.24"]` y repite el `uv add`: resuelve a la **1.23.2** (la última con wheel Intel). Detalle en el [Módulo 00](/modulo/00-preparar-el-terreno). Solo afecta a Macs Intel. |
| El script "se queda pensando" sin imprimir | Está esperando a la API (normal en la primera llamada) o el stream no vacía el buffer. | Dale 15–30 segundos. En streaming, imprime con `flush=True` como hacen los ejemplos. |
